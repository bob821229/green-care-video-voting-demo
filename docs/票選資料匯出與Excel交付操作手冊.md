# 票選資料匯出與 Excel 交付操作手冊

本文件說明如何使用 `database/reports` 內的唯讀 SQL Script，從 GreenCare SQL Server 匯出票選資料，整理成業主可閱讀的 Excel，並保留可稽核的原始檔案。

## 一、報表檔案與用途

| 執行順序 | SQL Script | 建議 Excel 工作表／檔名 | 資料分級 | 內容 |
|---|---|---|---|---|
| 1 | `001_export_manifest.sql` | `匯出資訊`、`Schema版本` | 內部 | 資料庫名稱、伺服器、匯出時間、各資料表筆數及 Schema 版本 |
| 2 | `002_video_catalog.sql` | `作品清單` | 可交付業主 | 正式作品編號、名稱、團隊、組別、YouTube ID、排序與啟用狀態 |
| 3 | `003_vote_summary.sql` | `票選結果` | 可交付業主 | 各作品排名、有效票、待確認票、取消票、作廢票與有效票比例 |
| 4 | `004_vote_detail_controlled.sql` | `投票明細_受限` | 受限 | 每筆投票、觀看門檻、裝置識別碼及不可逆雜湊 |
| 5 | `005_risk_and_audit.sql` | `風險事件_受限`、`稽核紀錄_受限` | 受限 | 風險事件與系統稽核紀錄；此 Script 會回傳兩個結果集 |

所有 Script 均使用 `SELECT` 查詢，不會新增、修改或刪除正式資料。執行前仍必須確認 SSMS 上方選取的是正確資料庫。

## 二、活動期間的臨時查詢

活動進行中若只需要確認即時票數，可執行：

```text
database/reports/003_vote_summary.sql
```

此查詢不會鎖定活動或停止投票，查詢完成當下之後仍可能有新票進入，因此不能直接視為活動最終結果。

## 三、活動結束後的正式匯出順序

1. 確認活動截止時間已到，網站不再接受投票。
2. 停止正式站 IIS App Pool，避免匯出過程仍有資料寫入。
3. 建立正式資料庫完整備份 `.bak`，並完成一次還原驗證。
4. 在 SSMS 連線正式 SQL Server，選擇 `GreenCare_Production`。
5. 依序執行 `001` 至 `005`。
6. 將每個查詢結果另存為 UTF-8 CSV。
7. 依本文件的核對規則確認筆數與有效票總和。
8. 將 CSV 匯入 Excel，建立業主閱讀版 `.xlsx`。
9. 為 `.bak`、CSV、Excel 計算 SHA-256，連同匯出時間與 Git commit 一起保存。
10. 若結果站仍需開放，確認 API 已不再接受投票後再啟動 App Pool。

測試站驗收時可對 `GreenCare_Development` 執行相同步驟，但測試結果不得當作正式交付資料。

## 四、使用 SSMS 匯出 CSV

### 方式 A：結果格線另存新檔

1. 在 SSMS 開啟要執行的 `.sql`。
2. 確認工具列資料庫不是 `master`，而是目標 GreenCare 資料庫。
3. 按「執行」。
4. 在下方結果格線按右鍵，選擇「將結果另存新檔」。
5. 儲存為 `.csv`。
6. `001` 與 `005` 會產生兩個結果格線，兩個格線都要分別儲存。

建議檔名：

```text
20261023_綠照好時光_匯出資訊.csv
20261023_綠照好時光_Schema版本.csv
20261023_綠照好時光_作品清單.csv
20261023_綠照好時光_票選結果.csv
20261023_綠照好時光_投票明細_受限.csv
20261023_綠照好時光_風險事件_受限.csv
20261023_綠照好時光_稽核紀錄_受限.csv
```

### 中文亂碼處理

若直接雙擊 CSV 後中文亂碼，不要在 Excel 中直接覆存：

1. 開啟空白 Excel。
2. 選擇「資料」→「從文字/CSV」。
3. 選取 CSV。
4. 檔案原始格式選擇 `65001: Unicode (UTF-8)`。
5. 分隔符號選擇逗號。
6. 載入後再另存成 `.xlsx`。

## 五、建議的 Excel 結構

建立一份 `綠照好時光_票選資料交付_YYYYMMDD.xlsx`，工作表依序為：

1. `匯出資訊`
2. `Schema版本`
3. `作品清單`
4. `票選結果`
5. `投票明細_受限`
6. `風險事件_受限`
7. `稽核紀錄_受限`

建議將每張工作表轉為 Excel 表格並開啟篩選，但不要覆寫原始 CSV。日期欄位同時保留 `Utc` 與 `Taipei` 欄位；一般閱讀優先使用 `Taipei` 欄位。

如果只交付公開結果，可另外建立精簡版 Excel，只包含：

- `匯出資訊`
- `作品清單`
- `票選結果`

受限工作表不可放入公開版或寄送給未授權人員。

## 六、匯出後核對規則

至少完成以下核對：

1. `001` 的 `VideoCount` 應為正式啟用作品預期數量；本活動預期為 30 部。
2. `001.ValidVoteCount` 應等於 `003.ValidVotes` 全部加總。
3. `001.VoteRecordCount` 應等於 `004` 的資料列數。
4. `003` 每個組別的排名應由有效票數由高至低排列；同票時依 `VideoId` 由小至大。
5. `002` 的作品編號、名稱與組別應與業主核准的正式名冊一致。
6. `004` 的 `WatchedPercentage` 應可佐證投票時已達有效觀看門檻。
7. 記錄匯出所使用的資料庫名稱、Git commit、應用程式發布包及匯出人員。

若以上任一項不一致，先停止交付並重新確認資料庫、活動狀態與查詢版本，不要直接在 Excel 手動修改票數。

## 七、敏感資料與存取限制

`004`、`005` 含有假名化識別碼及安全訊號，即使不是原始 IP，仍視為受限資料：

- 只提供給經授權的承辦或稽核人員。
- 不放在公開網站、一般共用雲端資料夾或公開 Git Repository。
- 不以一般通訊軟體任意轉傳。
- 不嘗試反查、比對或還原使用者身分。
- 不匯出 SQL 密碼、Connection String、Captcha Secret、AppSecret、Cookie 或原始 IP。

業主若只需要公布排名，提供 `003_vote_summary.sql` 的核准結果即可，不需要提供逐筆投票明細。

## 八、封存內容

正式活動結束後建議至少保存：

```text
database-backup/
  GreenCare_Production_YYYYMMDD.bak
raw-csv/
  001_匯出資訊.csv
  001_Schema版本.csv
  002_作品清單.csv
  003_票選結果.csv
  004_投票明細_受限.csv
  005_風險事件_受限.csv
  005_稽核紀錄_受限.csv
delivery/
  綠照好時光_票選資料交付_YYYYMMDD.xlsx
checksums/
  SHA256SUMS.txt
```

資料保存期限、存放位置及刪除日期應由主辦單位核准，並與隱私政策及內部個資規範一致。

## 九、SHA-256 計算範例

在 PowerShell 執行：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'D:\Exports\綠照好時光_票選資料交付_YYYYMMDD.xlsx'
```

CSV 與 `.bak` 也應分別計算並記錄雜湊。雜湊可證明交付後檔案是否被修改，但不能取代資料庫備份與存取權限控管。
