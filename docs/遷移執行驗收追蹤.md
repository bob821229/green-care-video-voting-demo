# GreenCare 遷移執行與驗收追蹤

## 文件用途

本文件是遷移工作的主要進度與驗收紀錄。技術細節參考：

- [技術棧遷移計畫書](./技術棧遷移計畫書.md)

- [本機測試 Checklist](./本機測試Checklist.md)
- [IIS 部署文件](./IIS部署文件.md)

後續每次執行任一階段時，必須同步更新本文件的階段狀態、Codex 驗收結果、使用者驗收結果、問題及日期。不得只修改程式而不更新本文件。

## 執行與驗收規則

1. 一次只執行一個階段，不提前實作後續階段。
2. 開始工作時，先將該階段改為「進行中」。
3. Codex 完成實作與自動檢查後，記錄修改檔案、測試指令及結果。
4. Codex 驗收通過後，狀態改為「待使用者驗收」。
5. 使用者確認無誤後，記錄確認日期並改為「已通過」。
6. 使用者確認前，不得自行開始下一階段。
7. 發現問題時改為「修正中」或「未通過」，修正後重新驗收。
8. 所有 SQL Server Schema 異動均以版本化 SQL 交付並人工執行，不使用 EF Core migrations。
9. 每個步驟完成時，Codex 必須提供使用者可執行的人工驗收方式、預期結果、自動測試涵蓋範圍及明確的通過回覆文字。

### 狀態定義

| 狀態 | 說明 |
|---|---|
| 未開始 | 尚未進行 |
| 進行中 | 正在實作或測試 |
| 修正中 | 驗收有誤，正在修正 |
| 待使用者驗收 | Codex 已驗收，等待使用者確認 |
| 已通過 | Codex 與使用者均確認通過 |
| 有條件通過 | 可繼續，但有已記錄的問題及期限 |
| 未通過 | 有阻擋問題，不得進入下一階段 |
| 不適用 | 雙方確認不需執行 |
