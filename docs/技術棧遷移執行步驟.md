# GreenCare 技術棧遷移執行步驟

> 實際執行狀態、Codex 驗收、使用者驗收與問題紀錄，統一維護於 [遷移執行驗收追蹤.md](./遷移執行驗收追蹤.md)。每次執行任何步驟時必須同步更新該文件；未取得使用者確認前，不得進入下一階段。

## 1. 原則

- 在 `codex/migrate-vue-dotnet-sqlserver` 分支進行。
- 新舊版本平行存在，完成驗收前不得刪除舊版。
- 每一階段完成後須執行測試並留下可回復的 commit。
- 不使用 EF Core migrations；所有 Schema 異動以版本化 SQL 交付並由人工執行。

- [x] 再次執行或執行前置檢查，確認不會誤覆蓋既有物件。
- [x] 以 SQL 查詢驗證 table、constraint、index、非法資料阻擋與權限。
- [x] 建立 EF Core entities、DbContext 與 Fluent mapping，使其與人工 SQL Schema 完全一致。
- [x] 禁止呼叫 `Database.Migrate()`、`EnsureCreated()` 或在正式啟動時執行 DDL。

前七項屬第 2 步；EF Core 兩項留待第 3 步。第 2 步完成條件：SQL 可人工建立、驗證及回復，應用程式角色無法異動 Schema。
