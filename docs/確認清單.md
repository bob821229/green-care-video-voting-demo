# 投票網站｜業主會議確認清單

> 會議目標：確認投票規則、觀看資格、身分識別與結果公布方式。以下項目會直接影響網站流程及程式設計，建議逐項確認並留下結論。

## 一、目前網站與設計稿的主要差異

| 項目 | 目前網站 | 業主設計稿 | 需要確認 |
|---|---|---|---|
| 作品分類 | 30 支作品未分組 | 個人組 15 支、團體組 15 支 | 是否確定分為兩組？ |
| 投票次數 | 每台瀏覽器裝置於活動期間限投 1 票 | 每人每天個人組、團體組各投 1 票 | 最終以哪一種規則為準？ |
| 投票後修改 | 送出後鎖定，不能改投 | 設計稿未說明 | 是否確定不能修改？ |
| 觀看資格 | 觀看欲投作品達 80% 才能投票 | 設計稿未呈現觀看門檻 | 是否保留 80% 規則？如何顯示？ |
| 身分識別 | 免登入，以瀏覽器裝置識別為主 | 僅寫一般民眾皆可參與 | 是否接受「每台瀏覽器裝置」而非嚴格「每個真人」？ |
| 投票結果 | 活動期間不公開即時排名 | 顯示排名、票數及進度條 | 結果何時公開？是否顯示精確票數？ |
| 作品瀏覽 | 搜尋與編號篩選 | 個人組／團體組頁籤 | 最終採用哪些瀏覽方式？ |

## 二、投票次數與規則

### 必須確認

- [ ] 最終投票規則是哪一種？
  - 活動期間每人總共只能投 1 票。
  - 每人每天只能投 1 票。
  - 每人每天個人組、團體組各投 1 票，每天最多 2 票。
- [ ] 個人組與團體組是否確定各有 15 支作品？
- [ ] 使用者可以只投其中一組嗎？
- [ ] 每日投票資格是否於台灣時間凌晨 00:00 重置？
- [ ] 同一位使用者隔天可以再投相同作品嗎？
- [ ] 投票送出後是否不能修改？
- [ ] 如果允許改投，可以修改幾次、修改到什麼時間？

### 建議

- 投票送出後不允許修改。
- 送出前顯示作品編號、片名及二次確認提示。
- 若採每日投票，明確寫成「每台瀏覽器裝置每天每組限投一票」。

## 三、觀看 80% 的投票資格

### 必須確認

- [ ] 是否確定保留「觀看影片達 80% 才能投票」？
- [ ] 是觀看欲投的那支影片達 80%，還是必須觀看全部作品？
- [ ] 每支影片是否獨立計算觀看進度？
- [ ] 暫停或離開頁面後，觀看進度是否保留？
- [ ] 如果採每日投票，隔天投相同作品是否需要重新觀看 80%？
- [ ] 隔天改投另一支作品時，是否需要觀看新作品達 80%？
- [ ] 觀看達標後，投票資格的有效期限為何？
  - 當次開啟期間有效。
  - 當天有效。
  - 整個活動期間有效。
- [ ] 30 支正式影片的長度是否接近？
- [ ] 快轉及切換到背景分頁時，是否確定不計入有效觀看？
- [ ] 作品卡片是否顯示觀看進度與投票資格？

### 建議流程

1. 使用者選擇一支作品並開始播放。
2. 系統獨立記錄該作品的有效觀看進度。
3. 觀看達 80% 後，解鎖該作品的投票按鈕。
4. 使用者確認作品名稱後送出投票。
5. 投票成功後，鎖定該組當日的投票資格。

### 建議顯示狀態

- 尚未觀看：`觀看達 80% 後可投票`
- 觀看中：`已觀看 52%`
- 達到門檻：`投給這支作品`
- 已完成投票：`今日個人組已完成投票`
- 活動截止：`投票已截止`

## 四、投票者身分與防重複

### 目前網站的作法

- 不要求民眾登入。
- 第一次進站時，系統會在瀏覽器建立加密的匿名識別碼。
- 以瀏覽器裝置識別作為主要投票限制。
- IP、裝置特徵及投票頻率只用於偵測異常，不單獨作為封鎖依據。
- 不會取得手機序號、IMEI 或可直接辨識個人的硬體資料。

### 必須確認

- [ ] 是否確定採用免登入方式？
- [ ] 是否接受免登入只能做到「每台瀏覽器裝置限投」，無法百分之百保證「每個真人限投」？
- [ ] 是否需要改用 LINE、Google 或手機簡訊驗證？
- [ ] 是否接受使用者清除 Cookie、換瀏覽器或換裝置後，可能再次取得投票資格？
- [ ] 是否同意 IP 僅作異常判斷，不直接限制同一 IP 只能投一票？
- [ ] 可疑票數要直接阻擋，還是先標記後再判定？
- [ ] 投票前是否加入 Cloudflare Turnstile 機器人驗證？
- [ ] 投票說明是否揭露 Cookie、IP 及裝置資訊的防舞弊用途？

### 可向業主說明

> 免登入的優點是操作簡單，對長輩與一般民眾較友善；缺點是無法百分之百確認真人身分。如果要嚴格做到一人一票，就必須增加登入或手機驗證，但投票完成率可能下降。

## 五、投票結果與排名

### 必須確認

- [ ] 活動期間是否公開即時排名？
- [ ] 是否顯示每支作品的精確票數？
- [ ] 還是等活動截止並完成異常票審核後才公布？
- [ ] 個人組與團體組是否分開排名？
- [ ] 每組公布前幾名？
- [ ] 「其他作品排名」是否顯示全部作品？
- [ ] 排名與票數多久更新一次？
  - 即時更新。
  - 每小時更新。
  - 每日更新。
  - 活動結束後才公布。
- [ ] 可疑或待確認票數是否列入前台排名？
- [ ] 異常票移除後，前台排名是否自動重算？
- [ ] 兩支作品同票時如何排序？
- [ ] 結果頁是否註明「最終結果以主辦單位公告為準」？

### 建議

- 活動期間不顯示精確票數及即時排名。
- 活動期間可顯示總參與人次，呈現活動熱度。
- 活動截止並完成異常票確認後，再公布正式名次與票數。

### 原因

- 避免從眾效應影響投票選擇。
- 避免落後作品支持者針對票差補票。
- 降低灌票者利用精確票數操作排名的機會。
- 避免尚未排除異常票時，排名頻繁變動造成爭議。

## 九、頁面與手機操作

### 必須確認

- [ ] 首頁是否依設計稿改為個人組／團體組頁籤？
- [ ] 一次只顯示一個組別，還是仍可瀏覽全部 30 支作品？
- [ ] 是否保留作品名稱或編號搜尋？
- [ ] 是否需要作品編號篩選？
- [ ] 手機版每列顯示一張還是兩張作品卡片？
- [ ] 點擊圖片是否開啟同頁播放器？
- [ ] 是否需要獨立的作品介紹頁？
- [ ] 是否需要支援放大字體、鍵盤操作及高對比等無障礙需求？
- [ ] 是否針對長輩使用者加大按鈕及操作說明？

### 建議

- 手機版每列顯示一張作品卡片，避免文字及按鈕過小。
- 整張作品卡片皆可點擊播放，不只限於中央播放圖示。
- 投票按鈕至少提供清楚的文字狀態，不只以顏色區分。
- 不自動播放影片。
- 網路中斷或影片錯誤時，提供明確的重新播放按鈕。
